# LLMエージェントを走らせずに方策ごと埋め込む。その距離は本当にKLなのか

エージェントを比べたいとき、ふつうは走らせる。タスクを与えて、ロールアウトを取って、成功率を見る。これは高い。環境を動かす費用がかかるし、比べたい相手が増えるほど線形に増える。

2026年10月に出た **Agent Behavior Maps**（arXiv:2610.30014）は、走らせずに比べる方法を提案している。全員に同じ参照軌跡を採点させて、その対数尤度を並べたものを座標にする。座標が近いエージェントは、実際に動かしても似た動きをする、という主張である。

これを手元の Mac で小さく再現した。そのうえで、座標の取り方を情報幾何の側から選び直した。先に結論を書く。

- **中心的な主張は再現した。** 1つの LLM でハーネスだけを変えた9体では、座標距離が実測の軌跡 KL の順序を Spearman 0.975 で追う。論文の値は 0.95
- **ただし水準は合わない。** 推定値は実測 KL の4倍前後に出る。順序づけまでは使えるが、「このペアの KL は何 nats か」には使えない
- **座標を `log p` から `√p` に替えると、水準まで合う。** Spearman 0.990、過大評価は36ペア中 0。追加の前向き計算は0回。これは論文にない話で、筆者の考察である
- **地図の形は chat template が決めている。** 同じモデルのテンプレート有無の距離が、別モデル同士の距離の 86% に当たる。地図の上で近いことを「モデルが似ている」と読むと誤読になる

コードと全数値は GitHub に置いた。

https://github.com/Tdual/agent-behavior-maps-repro

すべてローカルの Mac（MPS、fp32）で動き、外部 API は使っていないので費用は0である。

## 何が提案されているのか

論文は、エージェントを「LLM とハーネスの組」と定義する。ハーネスとは、履歴をどれだけ見せるか、system プロンプトに何を書くか、温度をいくつにするか、chat template で本文をどう包むか、といった周辺の全部である。重みだけを比べる慣行から外れて、この組を1つの点として扱う。

座標の作り方は単純である。全員に共通の参照軌跡を用意して、その軌跡が実際に取った行動を、各エージェントに教師強制で採点させる。ロールアウトは1本も走らせない。

![座標の作り方](images/10_pipeline.png)

参照軌跡は全員で共通なので、採点された対数尤度の違いは、エージェントの違いだけから来る。本再現では24本・193ステップを使った。

## 座標はどうやって作るのか

ステップごとの対数尤度を並べ、平均を引いて、ステップ数の平方根で割る。これがステップ版の座標である。

![ステップ版の座標](images/50_eq_step.png)

Mはステップの総数で、本再現では193である。軌跡版は、ステップごとの値を軌跡内で合計して軌跡1本につき1つの数にし、軌跡の本数の平方根で割る。

論文が証明しているのは、この座標距離の2乗が、仮定のもとで軌跡の対称 KL に一致するということである。仮定は2つある。局所性（どの許容行動でも2体の対数比が小さいこと）と、参照軌跡の分布がエージェント自身の辿る分布からそれほどずれていないこと。

## 再現してみた

小さいモデル6つ（SmolLM2 の135M・360M、Qwen2.5 の0.5B、Pythia 410M）と、ハーネス9通りを用意した。環境は ALFWorld 風の自作で、1ステップごとに許容行動の一覧を持つ。この一覧があるので、ステップごとの KL は推定ではなく閉じた式で出る。

![論文の結果と本再現の判定](images/01_claims.png)

5つの結果のうち3つは再現、1つは条件つきで再現、1つは測れなかった。

![座標距離は実測の軌跡KLを追うか](images/02_kl.png)

順位相関 0.975 は論文の 0.95 を上回っている。一方で右端の水準比は4倍前後で、論文も自分の設定で 7.5倍と報告している。ここは論文も主張していない。座標距離が使えるのはペアの順序づけまでである。

![9体の地図](images/20_map_a1.png)

9体を座標距離から古典的 MDS で平面に置いたもの。色は履歴の窓・system プロンプト・温度の群を表す。温度だけが違う4体が1か所に集まり、窓を狭めるほど離れていく。なお論文 図1(a) の落とし方は t-SNE だが、ここは MDS にした。平面距離が元の距離の順位を保つ度合いは MDS のほうが高かった（論文と同じ6体の設定で 0.975 対 0.821）。

### どこで再現しないか

論文が KL との照合に使っているのは「別々の LLM 同士」の構成である。これが再現しない（Pearson 0.324 / Spearman 0.393）。

分かれ目は、論文が条件に挙げた局所性ではなかった。ハーネス集合のほうが相関が出るのは、比べるペアが近いものから遠いものまで揃っているからである。6つの小さい LLM は互いに遠すぎて、軌跡がほとんど何も共有しない。正規化編集距離の中央値は 0.938、最大 1.000 で、挙動の近さを比べる余地がない。

もう1つ、小さい集合で検証するときの落とし穴がある。ロールアウトの乱数を共有しないと、同一エージェントを2回走らせただけで編集距離 0.44〜0.58 の差が出る。この雑音の床に信号が埋もれる。

**ここから先は論文に書かれていない。** α 表現の族から座標を選び直すという見方、その族の端点として論文の座標を位置づけること、α=0 の座標と上下の評価、そしてここに載せた測定は、どれも筆者の考察である。論文が述べているのは α=1 の座標とその局所での保証までで、座標の選び直しには触れていない。

## 情報幾何から座標を選び直す

困りごとが2つ残っている。推定値が実測 KL の4倍に出ること。もう1つ、論文が条件に挙げた局所性の定数が、指標として使えないこと。

後者を説明する。この定数は許容行動すべてにわたる対数比の最大値である。`log p` は確率が0に近づくと発散するので、一度も選ばれない行動が1個あるだけで、その1個が定数を決めてしまう。

![裾の扱い](images/30_tail.png)

横軸はその行動に方策が置く確率、縦軸は座標の値。左端の領域は、方策がほとんど確率を置いていない行動である。`log p` はここで下に落ちていき、`√p` は0に収束する。

確率を `p^((1−α)/2)` で埋め込む族がある。Amari の α 表現で、論文の座標は α=1、つまり `log p` にあたる。

![α 表現の族](images/03_alpha.png)

### なぜ log でなければならないのか

先に、α=1 を積極的に取る理由を書いておく。族から1点を適当に選んだわけではない。

- **KL の定義そのもの。** `KL(p‖q) = E_p[log p − log q]`。2体の座標の差が KL につながる形を作るなら、座標は log でなければ差が取れない
- **自己回帰の分解と KL の連鎖律が、どちらも log で和になる。** 軌跡の確率はステップごとの積で、1行動の確率はトークンごとの積である。積を和にするのは log だけで、`√p` では系列のぶんを足し合わせられない
- **α=1 は指数型分布族の自然座標であり、この座標では分布の空間が平坦になる。** 平坦だから、差のベクトルの足し算に意味がある。論文が付録で主張する「ハーネスの変更2つを足すと、両方を加えたときの変位になる」はこの平坦さに乗っている

実装の理由もある。`log p` は記録された行動1個の対数確率なので、1回の前向き計算で取れて、許容行動の集合を列挙しなくてよい。100体を並べるなら、これがいちばん安い観測量である。

ずれが出るのは次の一手にある。KL は符号つきの期待値だが、座標距離は対数比を重みなしで並べた2乗ノルムである。1次の期待値から2乗和へ移るところでテイラー展開が入り、ここで局所性が要求される。論文は、系列の足し算と合成には正しい座標を取り、そこにユークリッド計量を載せている。後半だけが局所的にしか正当化されない。

### α=0 で成り立つこと

写像 `p → 2√p` は、確率単体の Fisher–Rao 計量から半径2の球面への厳密な等長写像である。テイラー展開も局所性の仮定も入らない。

![ヘリンジャー距離](images/51_eq_hel.png)

これが2点を結ぶ**弦**の長さで、Hellinger 距離である。BC はバッタチャリヤ係数で、2点のなす角の余弦にあたる。

![Fisher-Rao 測地線距離](images/52_eq_geo.png)

こちらが球面に沿った**弧**の長さで、Fisher–Rao 計量による測地線距離である。曲がった面の上で2点の隔たりを計量どおりに測るなら、弧のほうが正しい。どちらが実際に良いかは測れるので、後の表では別の行として並べた。

![上下の評価](images/53_eq_bounds.png)

左は局所での近似、右は大域で常に成り立つ下限である。この等長写像によって、`log` の座標では成り立っていなかった4つのことが成り立つ。

- **局所性の仮定が要らない。** α=0 の球面への写像は展開を含まない等式なので、局所性の定数がどれだけ大きくても崩れない
- **裾の1個に定数を握られない。** `√p` では裾の寄与が0に収束するので、確率の小さい行動は距離をほとんど動かさない
- **距離が大域で距離になる。** Hellinger 距離は有界で対称、三角不等式を満たす
- **外す向きが決まっている。** 測地線距離から出る評価は KL の下限として大域で常に成り立つ。推定が KL を過大評価することがない

引き換えに失うのが、3つ目の理由に挙げた平坦さである。これは後で測る。

第2節で、座標には参照の生成器が取った1個の行動しか残らないと書いた。方策ベクトルを丸ごと保存しておけば、各参照履歴での `√p` を繋いだベクトルが作れる。本再現では最初から全部保存してあるので、**追加の前向き計算0回**でこの座標が計算できた。

### 測った結果

目標を「参照分布の下での厳密な KL」に置くと、参照履歴の選び方が全員で共通になるので、埋め込みの良し悪しだけが見える。

![埋め込みの誤差だけを見る](images/04_embed.png)

順位相関は 0.932 から 0.990 へ上がり、水準比は 3.69倍の過大評価から 0.87 になった。範囲の上端は 1.00 を超えない。

![水準比の比較](images/32_ratio.png)

α=1 は中央値で3.5倍以上に出て、上端は14を超える。α=0 は範囲ごと 1.0 の下にとどまる。理論が言う下限の向きが、実測でそのまま成り立っている。

温度だけが違うペアの退化も消える。論文の座標では、温度を変えただけの2体が距離ちょうど0になってしまう。許容集合の softmax の温度は、記録された行動1個の対数確率には現れないからである。α=0 では 0.3598 になり、厳密 KL の 0.3633 と3桁一致する。

![α=0 の座標で置き直した地図](images/33_map_a0.png)

図の形は α=1 と似ているが、距離の水準が実測 KL と揃っている。

### α=0 の座標はベクトルとして成立するのか

距離が直っても、まだ半分である。論文は地図を2つの用途で使っている。1つは距離で、もう1つは変位の足し算である。α=0 がこちらを壊すなら、それは論文の座標の代わりにはならず、より良い距離にとどまる。

壊れると疑う理由がある。各参照ステップの `√π` はノルム1を満たすので、エージェントは単位球の積の上に乗る。実際に測ると、22体すべてでノルムが1と一致した。つまり座標の差は球面を貫く弦であり、接ベクトルではない。弦の和は弦にならない。

![弦と弧](images/31_sphere.png)

基準から見た1ステップあたりの角度は、最大で 1.475 ラジアンである。直角の 1.571 にほぼ届くステップがあり、そこでは2体の方策がほとんど直交している。曲がりが無視できるほど小さいとは言えない。

曲がっているなら、曲がりを織り込んで足せばよい。球面には、基準点の接平面へ変位を移す写像がある。Fisher–Rao の対数写像である。

![対数写像](images/54_eq_log.png)

弦を接平面に射影し、長さを弧長に伸ばす操作である。これを参照ステップごとに当てると、すべての変位が基準点1つの接空間に乗る。接空間は本物のベクトル空間なので、そこでは足し算が定義されている。

![変位の足し算](images/05_compose.png)

接空間に移しても、cos は小数第3位しか動かない。**曲率は合成の誤差の原因ではない。** 誤差を決めているのは成分どうしの相互作用で、これは α=1 でも同じだけ落ちる。ノルム比ではむしろ α=0 のほうが1に近い。

ただし対数写像は基準点1つで取っているので、別の基準から測った変位を足すには平行移動が必要で、基準をまたぐ合成は測っていない。

## chat template が地図の形を決めている

論文と同じ設定（ハーネスを固定して LLM だけを変える）で地図を作ると、妙なことが起きる。

![6つのLLMの地図](images/40_tsne.png)

同じ系列の3体が固まらず、Qwen2.5 の instruct 版と base 版が両端に離れている。重みが近いはずの組が遠い。

原因を切り分けた。6体すべてを、chat template を外した素のテキスト連結でもう一度採点した。system プロンプトと本文をそのまま繋ぐ形で、テンプレートを持たないモデルがもともと受け取っている形式である。重みもハーネスも参照軌跡も同じなので、差はテンプレートの寄与だけになる。

![テンプレートの寄与](images/41_template.png)

![テンプレートを外したときの移動量](images/06_template.png)

テンプレートを持たない2体がちょうど0しか動かないことが、測定が正しいことの対照になっている。テンプレートを持つ4体は大きく動き、同じモデルのテンプレート有無の距離は、別モデル同士の距離の 86% に当たった。テンプレートを外すと、6体の並びが入れ替わる。

これは手法の不備ではない。エージェントを「LLM とハーネスの組」と定義したのだから、テンプレートが効くのは定義どおりの帰結である。ただし、地図の上で近いことを「モデルが似ている」と読むと誤読になる。近いのはモデルではなく、プロンプトの包み方を含めた組である。

## 測れなかったこと

論文の5つの結果のうち1つ、座標の近傍から成功率を予測するというものは測れなかった。全エージェントが8タスク中0成功で、予測すべきばらつきがない。

原因は切り分けた。評価8タスクはオラクルなら打ち切り内で全部解ける。方策がオラクル行動に置く確率も、1手あたりでは一様の3倍ある。問題は確率の偏りで、特定のステップで自信を持って外している。

![温度と完走確率](images/07_success.png)

温度を下げると悪化する。1手の平均確率は上がるのに、完走確率は15桁落ちる。鋭くすると、外しているステップで誤った行動に確率が集まるためである。完走確率が 1e−05 の水準なので、8本でも988本でも成功は0になる。このモデルとこの環境の組では、成功率の予測は原理的に測れない。

そのほか、規模が論文の約50分の1であること、自作環境が ALFWorld 風であって本物ではないこと、著者の実装（非公開）と突き合わせていないことが、範囲の限界として残る。

## 考察

座標距離が KL からずれる原因は2つに分かれ、片方しか座標の取り方では直らない。

1つは埋め込みの誤差で、確率分布をどの座標でユークリッド空間に置くかという選択から出る。これは α=0 でほぼ解消した。もう1つは参照軌跡の分布と、エージェントが実際に辿る分布とのずれで、どの座標を選んでも等しく残る。参照分布の下での厳密 KL が、エージェント自身のロールアウト上の KL を予測する力（Spearman 0.931）が、参照集合から計算するあらゆる方法の上限である。

だから、この手法を良くする余地は座標ではなく参照集合の作り方にある。参照の生成器を替えたときの地図の動きは、同じ生成器で本数を取り替えたときの2倍から3倍大きい。参照を何本取るかより、何で生成するかのほうが効く。論文が自身の参照集合の出自を limitations に挙げているのは、この向きと一致する。

用途としては、順序づけまでは信用できる。似たエージェントを探す、置き換え候補を絞る、どの変更が挙動を大きく動かすかを見る、といった使い方には足りる。α=0 に替えれば水準も合うが、そのためには許容行動の集合を列挙して方策ベクトル全体を保存する必要がある。列挙できない自由生成では上位 k 個に切ることになり、この環境では k=50 で順位が完全に一致した。

## この論文の何が良いのか

再現してみて、設計の良さが2か所にあると思った。問いの立て方と、測る対象の定義である。

問いの立て方は「走らせずに位置づける」である。エージェントの評価は、環境を動かしてロールアウトを取る費用に縛られている。走らせる代わりに共通の参照軌跡を採点させるだけにすると、1体あたりの費用は参照ステップ数ぶんの前向き計算だけになり、環境の実行が消える。本再現がローカルの Mac で費用0で終わったのは、この設計のおかげである。100体を1枚の図に並べられるのは1体あたりが安いからで、安さは副産物ではなく出発点にある。

測る対象の定義は「エージェント = LLM + ハーネス」である。本再現で chat template が 86% を占めたことは、この定義の正しさの側の証拠として読める。テンプレートはモデルカードに載らないが、挙動を決めている。重みだけを比べる枠組みでは、この 86% は見えないまま残る。

手続きの面でも、追試できる形になっている。相関を見せて終わりにせず、距離の2乗が軌跡 KL に一致することを、局所性と参照のずれを明示した定理として書いている。条件が書いてあるから、本再現のように条件そのものを測って「この定数は裾の1個に支配されて指標にならない」と言える。仮定を書かない論文には、反証の足場がない。

文法マスクの有無で採点がどれだけ動くかを付録で実測し、100体の実験はマスクなしだと表に明記しているのも同じ性質である。この記述があったから、図1(a) の座標が許容集合で正規化されていない素の和であることを読み取れた。

座標の選び方も、α の族を調べたあとで振り返ると偶然ではない。KL を目標に置き、軌跡を1本のベクトルに畳むと決めた時点で、系列の積を和にできるのは log だけであり、合成が乗る平坦さも log 側にしかない。そのうえ `log p` は許容行動を列挙しなくても取れる。100体を安く並べるという目的に対しては、α=1 が正しい選択だった。本再現が示したのは、目的を「KL の水準まで合わせる」に変えると別の端点のほうが良くなる、という条件つきの話である。

走らせずに測るという枠組み自体は論文のものであり、座標の選び直しはその枠組みの中での改良にすぎない。枠組みが明示的に書かれていたから、どこを替えれば何が直るのかを測定で切り分けられた。
